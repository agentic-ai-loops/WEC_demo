# Task 1

Let's merge `/mcp` and `/graphql` into a single deployment server.  This means that we need to modify the CLI `svr`.

**start the server**
```
svr start 
    --host <host:str = "0.0.0.0">
    --port <port:int=8000>
    --run-dir <run_dir:Path = "./run">
```

- Writes the PID in the `{run_dir}/svr.pid`
- MCP server on `/mcp`
- Graphql server on `/graphql`
- Health status on `/health`

**stop the server**
```
svr stop --run-dir <run_dir:Path = "./run">
```

Shutdown the server.

**status**: getting the status
```
svr status
```

# Task 2: automatic re-rendering

- We want to implement a message queue using rq + redis.  Setup python libraries for this.
- The redis docker image is already pulled.
- Create a separate module to handle all job queue related models and functions.
- All mutations from graphql will enqueue a job with an argument that contains the update timestamp and the graphql mutation name.  (Use a pydantic model to model the message.)
- A separate worker process will consume these jobs.  It will trigger re-rendering of *all* the design templates using the active version of #businessdata.

The output will be now located in:
```
{run_dir}/sites/{workspace}/{design}/
```
