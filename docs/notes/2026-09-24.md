# Task 1: GraphQL and CLI

1. We are bring GraphQL into the picture as the workhorse to support #businessdata query and mutation. Setup the python strawberry library.

2. We want a single central CLI application to manage the servies:
  - graphql server with configurations
  - MCP server with configurations
  - status reporting of servers

3. We want a separate client CLI application to test the servers.
    - graphql client with generic graphql string
    - graphql schema inspection
    - MCP client query / mutation / resource / prompt

Both CLI are to be written using typer with colorized rich user interactions.

For this task, simply setup the development environment and the stubs:

Setup .env with:

```
GRAPHQL_HOST=0.0.0.0
GRAPHQL_PORT=9001
MCP_HOST=0.0.0.0
MCP_PORT=9002
```

## GraphQL

- a simple query "hello" that returns `{message: "hello world}`.
- the graphql server runs in `GRAPHQL_HOST:GRAPH_PORT`

## MCP server

- a simple tool "query(gql: str)" that will return the graphql string result.

## Server management CLI

```
# start server
uv run svr graphql

# check
uv run svr graphql --check

# start mcp server with optional starting of graphql
uv run svr mcp --start-graphql
uv run svr mcp --check
```

## Client CLI

```
# either read gql from string, or given in an option.
uv run client-cli graphql --stdin --gql "..."
uv run client-cli mcp --tool <tool-name>  --<param> <argument> --<param> <argument> ...
```

# Task 2: Business Data Storage and Access

Refer to @01-businessdata.md for the schema description.
Refer to @02-graphql-api.md for the graphql queries and mutations that will need to be implemented.

In this task, we will:

1. implement pydantic models that will store the intermediate results of query results.
2. create tables with foreign key constraints to store the entities while allowing efficient graphql queries and mutations.

Use idiomatic sqlalchemy with sqlite backend.

Also separate the code into their appropriate modules in @src/intelliw

Considerations:

- make sure that type modeling duplications are all necessary due to meeting the requirements of frameworks.  It seems that strawberry graphql requires its own types, while pydantic models are a good fit to represent the database query results.

- provide database queries through sqlalchemy and return the results as pydantic models.  Make sure they will be high impact in the implementation of the graphql resolvers.

# Task 3: Business Data Inspection

We want to build a CLI typer application `business`.  It reads `WORKSPACE` from @.env to determine the path to the workspace.

```
# print the statistics of different entities
# check for referential integrity
# check missing resources
# if version/tag not given, check active
business doctor --version <...>  --tag <...>
```

```
# dump the entire business data in indented JSON
# by default, only the active
business dump --version <version>

# list versions and their tags
business versions

# make a snapshot.
business snapshot --tag <tag-string>

# activate a snapshot by specifying a version or a tag string.
business activate --version <version> --tag <tag-string>
```
